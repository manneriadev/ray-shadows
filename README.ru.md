# Ray casting shadows

2D-тени в реальном времени на C и SDL2. Источник света испускает 300 лучей; каждый луч
останавливается на первом препятствии, которое встретит (круг или граница окна), поэтому
область за препятствием остаётся тёмной. Источник света можно перетаскивать мышью.

## Управление

| Действие | Результат |
|----------|-----------|
| Зажать кнопку мыши и двигать | перемещение источника света |
| Закрыть окно | выход |

Текущий FPS показывается в заголовке окна.

## Сборка и запуск

Нужны компилятор C и SDL2.

- **Windows (MSYS2 UCRT64):** `pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-SDL2 make`
- **Linux:** `sudo apt install build-essential libsdl2-dev`

```
git clone https://github.com/manneriadev/ray-shadows
cd ray-shadows
make
./ray        # ray.exe на Windows
```

## Как это работает

Каждый луч задаётся параметрически: `P(t) = O + t * (cos θ, sin θ)`, `t > 0`, где `O` это
центр источника света, а `θ = 2πi / N`.

- **Луч и круг.** Подстановка луча в уравнение `|P - C|² = r²` даёт квадратное уравнение
  `t² + B·t + C₀ = 0` с дискриминантом `D = B² - 4C₀`. При `D < 0` луч промахивается; иначе
  наименьший положительный корень это расстояние до точки попадания.
- **Луч и граница окна.** Пересечение с прямыми `x = 0`, `x = W`, `y = 0`, `y = H` даёт
  `t = (граница - O) / направление`; попадание засчитывается, если `t > 0` и вторая
  координата лежит в пределах окна.
- **Побеждает ближайшее.** Наименьшее допустимое `t` среди всех кандидатов и есть конец луча.

Все пересечения считаются по формулам, без пошагового движения луча и перебора пикселей.

## Заметки об оптимизации

Проект разрабатывался на виртуальной машине с малым объёмом памяти, поэтому
производительности уделялось особое внимание. Что используется в `src/ray.c`:

- синусы и косинусы всех углов лучей **вычисляются один раз** и хранятся в таблицах
- всё, что не зависит от луча (центр препятствия, `C₀`, положение света), **вынесено из цикла**
- `sqrt` вычисляется только при положительном дискриминанте
- круги рисуются **один раз** в текстуры, а не каждый кадр
- включена вертикальная синхронизация (vsync), поэтому цикл отрисовки не загружает процессор на 100%
